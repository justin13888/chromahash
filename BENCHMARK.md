# Chromahash Benchmark

**The measured figures live in [`spec/PERFORMANCE.md`](spec/PERFORMANCE.md).**
This file no longer publishes any.

## Why this file carries no numbers

It carried a cross-language table — encode/decode, single and bulk, seven
languages plus two ThumbHash baselines — generated by `tools/benchmark` on an
Apple M3 Pro. Every number in it had the two defects the performance fence was
built to stop:

- **Untraceable.** No automation regenerated it — `tools/benchmark` could still
  produce a table, but the instruction was a manual paste — nothing gated it, and
  no committed run backed it. Nothing in the repo so much as referenced this
  file. It sat outside the fence
  [`a92eb791bae3de9d2d9e8b63f23f1e8fe627ff39`](https://github.com/visualcommons/chromahash/commit/a92eb791bae3de9d2d9e8b63f23f1e8fe627ff39)
  built across `README.md` and `spec/README.md`, and was missed for exactly that
  reason.
- **Wrong about what it measured.** Its "single" column timed process startup.
  `spec/PERFORMANCE.md` §7 cites this file's own Kotlin and C# encode cells as the
  example: JVM and .NET cold start, published as though it were the algorithm.

Its regeneration instruction was also broken. It told the reader to run
`mise run benchmark` and paste `tools/benchmark/output/benchmark-summary.md`;
since the unified harness landed, `mise run benchmark` writes
`tools/comparison/output/perf/perf.json` instead, and no mise task runs
`tools/benchmark` at all.

## Where the numbers are now

| Was here | Now |
|---|---|
| Cross-language encode/decode, startup removed | [`spec/PERFORMANCE.md`](spec/PERFORMANCE.md) §7 |
| The old "bulk per-op" **compute** number | [`spec/PERFORMANCE.md`](spec/PERFORMANCE.md) §7 |
| Batch **throughput** across threads | [`spec/PERFORMANCE.md`](spec/PERFORMANCE.md) §8 |
| Per-tier cost, and what capping the raster buys | [`spec/PERFORMANCE.md`](spec/PERFORMANCE.md) §2 |

The old "bulk per-op" column splits across two of those rows on purpose. It was a
parallel encoder's wall-clock ÷ count printed beside GIL-bound Python, which
compares threading models rather than algorithms. §7 and §8 keep serial per-op
cost and machine-scaled throughput apart, and §8 opens by explaining why.

Those tables are bound to cell ids that `mise run verify:benchmark` resolves
against a committed run. There is none right now — the previous baseline was
withdrawn as unreproducible and `tools/comparison/baselines/` holds no perf run —
which is why every cell reads `TBD` and the gate **fails by design** until a
re-measurement lands. See the banner at the top of `spec/PERFORMANCE.md`, and
`TESTING.md` for the procedure — it is a deliberate act on a host that can hold a
clock still, and a laptop is usually not good enough.

## One thing that did not carry over

The unified harness has **no ThumbHash target**. The two baseline rows this file
carried — the official `thumbhash` crate and the JS reference — have no successor
in `spec/PERFORMANCE.md`, so cross-format *timing* against ThumbHash is currently
unmeasured. (`tools/comparison` still owns quality and bytes against ThumbHash;
this gap is wall-clock only.)
