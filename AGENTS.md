# chromahash

Modern, high-quality image placeholder representation for professional formats (LQIP).

This is a **monorepo** with six language implementations of the same format specification.

## Development

Language tooling is mostly managed by `mise` and common commands are run via `just`.

## Implementation Notes

- All six implementations MUST produce identical output for the same input — the spec in `spec/` is the source of truth
- Use strict TypeScript — no `any` types
- TypeScript: the full encode+decode path is a thin facade over the `chromahash-wasm` (`wasm-bindgen`) build, which is **async**: `await init()` once before encoding/decoding (browsers fetch the co-located `.wasm`; Node passes the bytes). `just ts-cbuild` stages the wasm-pack glue into `typescript/wasm/` (gitignored build output, biome-ignored). The lone hand-maintained algorithm port is `typescript/src/decode.ts` — a pure-TS, no-WASM-init **decode-only** module (exported as `@chromahash/typescript/decode`) for render-only consumers; `decode.test.ts` keeps it honest with a sync guard asserting bit-for-bit equality against the WASM decode over the spec vectors + a fuzz corpus
- Rust: `#![deny(warnings)]` on public crates once stable
- Kotlin: Kotlin DSL only (`.gradle.kts`), target JVM 21
- Swift: a thin facade over UniFFI-generated bindings (no native algorithm); Swift 6 concurrency, no `@unchecked Sendable` hacks. `just swift-cbuild` assembles the `ChromaHashFFI.xcframework` + generated bindings (build outputs). macOS via xcframework; Linux `systemLibrary` support is a follow-up
- Write tests for all public API surface and ensure they are consistent across languages and validates the specification in `spec/` completely
- Go: a thin **cgo** wrapper over `bindings/c` (no native algorithm). go.mod stays dependency-free, but builds need a C toolchain (`CGO_ENABLED=1`) and the static lib staged into `go/lib` — run `just go-cbuild` (done automatically by `just build-go`/`test-go`)
- Use conventional commits: `type(scope): description` — scope = `rust`, `c`, `ts`, `wasm`, `kotlin`, `jvm`, `swift`, `go`, `py`, `csharp`, `android`, `uniffi`, `spec`, `tools`, or `comparison`. Enforced by the `commit-msg` lefthook hook and the `ci-commits` workflow (convco) — non-conventional messages are rejected. (`convco` checks the conventional-commit *format* only; the scope list above is convention, not machine-enforced.)
- The CHANGELOG's `[Unreleased]` section (between the `<!-- git-cliff-unreleased-* -->` sentinels) is generated by `just changelog` (git-cliff). Don't hand-edit it except to add `Removed` entries; curated history below the sentinels is never regenerated. Releases are cut with `just release X.Y.Z` — see `RELEASING.md`.
- Keep implementations in sync — a feature in one language should land in all six
- Python: a thin facade over UniFFI-generated ctypes bindings (no native algorithm); still zero external *runtime* deps (ctypes is stdlib). `just python-cbuild` stages `chromahash/_uniffi.py` + the native lib (build outputs; the generated module is ruff-excluded). Use Ruff for both formatting and linting

## FFI bindings (`bindings/`)

The non-Rust languages bind to the zero-dependency `rust/` core through three FFI surfaces (issue #38 — collapsing the former native ports so spec changes land once):
- **`bindings/uniffi/`** (`chromahash-uniffi`) — UniFFI; serves Swift, Kotlin/Java (JVM + Android), and Python.
- **`bindings/c/`** (`chromahash-c`) — hand-written `extern "C"` + `cbindgen` header; the first-class C API and the foundation for C# (P/Invoke) and Go (cgo).
- **`bindings/wasm/`** (`chromahash-wasm`) — `wasm-bindgen`; the full encode+decode path for the TypeScript web package.

- Each binding crate wraps the core (`chromahash = { path = "../../rust" }`) and keeps the core itself zero-dependency — the `uniffi`/`cbindgen`/`wasm-bindgen` deps live only in their respective binding crates.
- **No Cargo workspace** — the core and each FFI binding crate are standalone; always pass `--manifest-path <crate>/Cargo.toml` to cargo (the justfile recipes do this). This is deliberate: the Android Gradle pipeline runs `cargo` from the crate dir, and isolating each crate keeps the core's dependency graph clean.
- `bindings/uniffi/android/` is the Gradle library module (AGP 9, built-in Kotlin) that packages the cross-compiled `.so` + generated Kotlin into an AAR.
- The generated `src/main/kotlin/` bindings and `src/main/jniLibs/*.so` are **build outputs** — gitignored and regenerated by `cargo ndk` + `uniffi-bindgen`. Don't hand-edit or "restore" them; run `just build-android-aar`.
- The enforced correctness gate is `just test-android` (Rust spec-vector test, no NDK). The AAR build (`just build-android-aar`) needs the Android NDK/SDK + `cargo-ndk` and is validated in CI's `ci-android` `aar` job.

## Architecture

Each sub-project is an independent library implementing the chromahash LQIP format:
- **Encoding**: convert an image into a compact placeholder representation
- **Decoding**: reconstruct a low-fidelity preview from the placeholder
- **Format spec**: defined in `spec/` — all implementations must pass the same test vectors
